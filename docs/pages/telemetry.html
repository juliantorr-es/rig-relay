Tracing Policy

Every release-critical golden-path stage emits a correlated trace event carrying trace_id, span_id, and handshake_id. The app does not 'work' until the golden path can prove it worked from one correlated trace.

Content-Light Doctrine

Trace payloads are content-light. No token values, no full file contents, no prompt payloads, no model outputs.

Redaction Rule

token_value_included must always be false in emitted golden-path traces. token_present may be true as a boolean.

Correlation

Desktop/frontend/WebSocket events must carry handshake_id for cross-subsystem correlation.

Strict Mode Stages

  1. bridge started
  2. server bound
  3. frontend booted
  4. runtime config loaded
  5. websocket connected
  6. auth ok
  7. projection sent
  8. projection received
  9. projection rendered
  10. status rendered
  11. ready reached
  12. shutdown observed

Failure Conditions

missing_trace_id
Cannot correlate. Useless breadcrumb confetti.
missing_handshake_id_on_desktop_frontend_websocket_events
Cannot join frontend to bridge.
token_value_appears_anywhere
Security bug. Straight to airlock.
frontend_auth_ok_without_desktop_websocket_auth_ok
Split-brain auth trace.
desktop_projection_sent_without_frontend_projection_received
Transport/protocol seam broke.
frontend_projection_received_without_frontend_projection_rendered
Renderer seam broke.
frontend_status_rendered_contradicts_reducer_state
UI is lying.

Degradation Policy

Degradation policy derived from tracing policy and consent enforcement rules. When telemetry is disabled, all optional tracing stops. Mission-critical receipts remain. The UI shows a degraded-mode indicator.

Redaction Rules

  • Token values must never appear in telemetry (token_value_included: false)
  • Full file contents must never be emitted
  • Secrets and credentials are always redacted
  • Prompt payloads and model outputs are excluded
  • Content-derived data uses SHA256 hashes only
  • Home directory paths are replaced with [REDACTED]
