Orchestrator Loop Boundary

Principle 1 — Only an Owner May Run a Full Turn Loop

An owner faces the user (directly or through an adapter), owns the session, decides delegation/handoff/approval/disposition, synthesizes final answers, and controls merge/push. Owners: desktop cockpit, ACP server, IDE sidecar. Subagents, Ralph, and test fixtures are NOT owners.

Principle 2 — OrchestratorLoop

OrchestratorLoop (currently AgentLoop) owns user-facing turn orchestration, model call sequence, tool-call planning, delegation/handoff decisions, approval boundaries, mission assignment, and final synthesis. It is the only entity allowed to run a full turn loop.

Principle 3 — ConversationRuntime

ConversationRuntime owns turn phase state (_phase(), _finish()), loop decision policy (decide_after_middleware, decide_after_model_turn, decide_after_hook_processing, decide_after_tool_batch, decide_after_budget_check), outcome classification, trace/phase evidence (PhaseTraceHook, PhaseTraceAttributes), and JSON-safe result (build_result()).

Principle 4 — SubagentRuntime (IMPLEMENTED v1)

Owns

  • Bounded mission execution
  • Lifecycle evidence emission via TraceRecorder
  • Explicit tool_execution_mode marker
  • Structured SubagentResult with metadata
  • Assigned lane/worktree
  • Allowed tools/profile/model binding
  • Budget (turns, price, time)
  • Expected artifact contract
  • Validation receipt
  • Patch proposal or report output

Does NOT Own

  • Global session history — scoped to mission
  • Final user-facing answer — synthesized by owner
  • Global approval policy — inherited from owner
  • Unbounded tool loops — budget-enforced
  • Merge/push — orchestrator-only
  • Switch_agent / compact / fork — bounded lifecycle

Principle 5 — RalphRuntime (Planned)

RalphRuntime will use SubagentRuntime with profile_kind=AUTONOMOUS_BACKGROUND and trust_tier=OBSERVE. Owns background observation (read-only), report generation, proposal output. No normal assignable missions. No merge/push.

Principle 6 — ToolRuntime

ToolRuntime owns governed tool execution. It is NOT a loop owner. See docs/governance/tool-runtime-boundary.md.

Principle 7 — Handoff Receipt

Ownership transfer (e.g. orchestrator to subagent) requires a handoff receipt with the following fields:

FieldDescription
owner_beforeSession/agent ID of delegator
owner_afterSession/agent ID of subagent
reasonWhy the handoff is needed
scopeWhat the subagent may do
budgetTurns, price, time limits
return_conditionWhen ownership returns
trace_idFor observability correlation

Phase 3 Recommendation

  1. Move the while-loop into ConversationRuntime.execute_turn() — OrchestratorLoop becomes thin adapter
  2. Do not create full AgentLoops for subagents — SubagentRuntime is bounded
  3. Do not give Ralph any loop ownership — uses SubagentRuntime with AUTONOMOUS_BACKGROUND
  4. AgentLoop rename to OrchestratorLoop only after SubagentRuntime exists

AgentLoop Refactor — Extracted Runtimes (Waves 2-6)

Waves 2-6 reduced AgentLoop from 1806 to 991 lines (45% reduction) by extracting 5 standalone runtime modules. Each module owns a coherent domain and is composed into AgentLoop — none use MRO mixin injection. Ownership boundaries are explicit and testable.

ToolExecutor (rig_relay/core/tool_executor/, 782 lines)

  • Adapter factory — constructs tool adapters from registered tool types
  • Council gating — adversarial multi-provider review before mutation
  • Execution orchestration — single tool invoke with all pre/post hooks
  • Concurrency — parallel tool batch execution with lease coordination
  • Does NOT own approval policy (delegates to GovernanceRuntime)

SessionRuntime (rig_relay/core/session_runtime.py, 292 lines)

  • Fork — clone session into isolated lane with bounded message history
  • Compact — collapse message history to conversation digest
  • Clear history — reset message list while preserving session identity
  • Switch agent — rebind profile/model/tools without session teardown
  • Reload — rehydrate session from config with optional initial messages
  • Runtime state — build and update AgentRuntimeState snapshot

GovernanceRuntime (rig_relay/core/governance_runtime.py, 101 lines)

  • Permission gating — per-tool ALWAYS/ASK/NEVER enforcement
  • Approval policy — tool approval callbacks, user prompt construction
  • Write gating — mutation tool legality checks before execution
  • Session rules — per-session policy overrides and constraints

TraceRuntime (rig_relay/core/trace_runtime.py, 85 lines)

  • Correlation IDs — trace/turn/session ID propagation across boundaries
  • OTel spans — span construction, attribute binding, parent-child linking
  • Lifecycle events — session start/end, turn start/end event emission

TurnEnvelope (rig_relay/core/conversation_runtime/turn_envelope.py, 58 lines)

  • Canonical turn result with 11 structured fields
  • Fields: status, outcome, tool_batch_metadata, phase_trace, budget_consumed, model_call_info, middleware_results, tool_results, context_used, evidence_emitted, correlation_id
  • JSON-safe serialization for projection consumers
