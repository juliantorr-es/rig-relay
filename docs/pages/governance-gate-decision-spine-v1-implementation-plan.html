Governance Gate Decision Spine — Implementation Plan

Architecture Decision

Use one canonical event (rig.relay.governance.gate.decision) with a decision field carrying one of six outcomes. Do NOT create paired event names (allow/block). This aligns with OpenTelemetry semantic conventions, OWASP security logging guidance, and NIST SP 800-92.

Phase 0: Schema + Emitter + Golden DuckDB Test

Add rig.relay.governance_gate_decision.v1 schema. Add emit_governance_gate_decision() function — not send_governance_gate_decision() that chooses between separate event names. Write one golden DuckDB projection test that proves the event shape is groupable by gate, decision, reason, tool_name, and severity.

Phase 1: Cryptographic + Policy-Missing Seams (highest risk)

Crypto gaps are not Phase 4 polish — they are Phase 1. If the local action envelope silently returns False on signature failure, payload hash mismatch, or replay expiry, that is missing security audit evidence at the boundary where Rig claims to be governed.
