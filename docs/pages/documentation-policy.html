Documentation Policy

New project documentation must be written as canonical JSON artifacts using the rig.documentation.page.v1 schema. Markdown is only permitted for explicitly allowed exceptions. Old Markdown docs must be migrated to JSON before deletion.

Allowed Markdown Exceptions

  • AGENTS.md — agent instructions
  • README.md — GitHub landing page
  • CONTRIBUTING.md — contribution UI
  • CONTRIBUTOR_LICENSE_AGREEMENT.md — legal
  • LICENSE — plain license text
  • ATTRIBUTION.md — human-readable attribution
  • CHANGELOG.md — if release tooling requires it

Migration Rules

  1. JSON replacement must exist and validate against a schema
  2. Static renderer must render it
  3. Migration manifest must map old_path to new_path
  4. References must be updated
  5. Tests must pass
  6. Deletion must be listed in the final report

Required Schema Validation

  • rig.documentation.page.v1 — individual documentation pages
  • rig.documentation.collection.v1 — named document collections
  • rig.documentation.migration_manifest.v1 — migration tracking
  • rig.documentation.site_manifest.v1 — site navigation structure
  • rig.code_schema.v1 — governed implementation contracts
  • rig.code_schema.plan.v1 — integration plans for the context assembler

Code Schemas

Recurring implementation patterns should be written as JSON code schemas under docs/json/code_schemas/ and validated against docs/schemas/rig.code_schema.v1.schema.json. Code schemas are governed contracts for retrieval and context packing, not code templates.

Static Site Rendering

Documentation is rendered to static HTML by scripts/render_static_docs.py. The generated site is committed under docs/ and published via GitHub Pages from the main branch /docs folder. No custom GitHub Actions workflow is required.
