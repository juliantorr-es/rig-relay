AgentLoop Governance Fail-Open Inventory and Orchestration Split

Audit date: 2026-05-20. This document captures the governance paths that currently fail open, the graceful-degradation behavior each one should use instead, and the orchestration split needed to keep AgentLoop from absorbing more policy and tracing logic.

Shared Degradation Rules

  • Mutation gate failures resolve to `BLOCK`, `REVIEW`, or `DEGRADED`, never `ALLOW`.
  • Read-only tools may continue when the only problem is governance availability.
  • Missing evidence must surface as `unknown`, not `none`.
  • Dev bypass is only acceptable when it is explicitly enabled and labeled in the policy path and receipt path.
  • Policy hints remain advisory until a policy object is injected into the executor.
  • Coordination failure should produce a dry-run or refusal, not an unleased write.

Patch Order

  1. Convert the fail-open branches to typed degraded refusals before adding any new orchestration split.
  2. Make `ToolRuntime` require an explicit policy object or fail closed when the policy is missing.
  3. Thread the policy object through the runtime execution runner so metadata hints are enforced, not just recorded.
  4. Extract governance decisions out of `AgentLoop` into a dedicated governance boundary.
  5. Add tests for the fail-open, degraded, and trace-propagation paths before renaming or flattening the shell.
