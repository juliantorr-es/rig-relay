Governance Gate Decision Spine Audit

Core Finding

The gap is emission, not infrastructure. Rig Relay already has telemetry events, trace spans, receipts, structured logs, and DuckDB projections. The governance failure paths use them. The governance success paths do not. This means you can debug refusals but cannot study governance behavior — you can answer 'why did this fail?' more often than 'how often did the right gate allow, block, degrade, or require review under comparable conditions?'

Canonical Event Shape

Do not create paired event names (allow/block). Use one canonical event: rig.relay.governance.gate.decision with a decision field carrying one of six outcomes.

{
  "schema_version": "rig.relay.governance_gate_decision.v1",
  "event_name": "rig.relay.governance.gate.decision",
  "gate": "dirty_guard",
  "decision": "allowed",
  "reason": "file_was_clean",
  "tool_name": "write_file",
  "mutation_intent": true,
  "policy_version": "v1",
  "severity": "info",
  "receipt_id": "rcpt_abc123",
  "trace_id": "tr_abc123",
  "span_id": "sp_abc123",
  "content_light": true,
  "operator_action_required": false
}

DecisionMeaningSeverityExample

reviewGate declined to decide automatically; requires human reviewwarningcouncil: single_provider
failed_closedInfrastructure/configuration broke; Rig denied by safety defaultcriticaltool_runtime: policy_object_missing
degradedSystem continued with reduced guaranteeswarningcontext: collision_evidence_missing

Why One Event, Not Paired Events

  • Aligned with OpenTelemetry semantic-conventions: common names and stable attributes make telemetry comparable across traces, metrics, logs, and resources.
  • OWASP security logging guidance: security controls should be logged whether they succeed or fail, in a format log-management systems can consume.
  • NIST SP 800-92: audit records should include successful and failed authentication attempts, file accesses, policy changes, and privilege use.
  • DuckDB groupability: one event name with decision/severity/gate/reason columns is directly queryable without UNION or event-name prefix matching.

Volume Management

Success tracing can become noisy. Following Google SRE guidance, Rig should emit all governance decisions to structured JSONL/telemetry but alert only on critical classes. Analyze allowed/refused distributions through DuckDB/reporting, not through alert spam.
