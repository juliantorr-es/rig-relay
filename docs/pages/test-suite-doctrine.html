Test Suite Doctrine

Purpose

Rig Relay ships a test suite of 6,500+ collected tests. Without a doctrine, the suite accumulates debt: root-level orphan tests, mis-scoped test files buried in tests/scripts/, duplicate assertions across files, pycache-dependent collection, and tests that pass on one machine but fail on a clean clone.

Layout Rule

Every test file must live under a path that mirrors its target source package. tests/core/test_agent_loop.py is correct. tests/test_agent_loop.py is a layout violation.

  • Root-level tests/test_*.py files are violations unless explicitly allowed
  • tests/scripts/test_*.py files whose target source is not scripts/ are violations
  • Canonical tests map 1:1 with rig_relay/ package structure

Parametrization Rule

Tests with identical setup/act/assert skeletons must be consolidated into parametrized tests with explicit case IDs. Use pytest.mark.parametrize and pytest.param(id='explicit_case_id'). Case IDs must be stable, behavior-based, and free of vague names like case1/case2/happy/sad.

Duplication Rule

Each test behavior must exist in exactly one place. When a concern grows large enough for its own file, the original tests must be removed. Duplicate test bodies create maintenance burden and naming collisions.

Test Lifecycle

  1. Write behavior-named test in correct layout directory
  2. If test body matches existing test, parametrize instead of copying
  3. If test concern grows >10 related tests, extract to own file, remove originals
  4. Run PYTHONDONTWRITEBYTECODE=1 uv run pytest before claiming green
  5. Run uv run ruff check --fix and uv run ruff format after changes
  6. Delete stale tests targeting removed modules; never xfail/skip to hide deletion debt

Layout Audit

tests/architecture/test_test_layout.py provides a report-only layout guard detecting root-level orphans, mis-scoped scripts/ tests, and known duplicate pairs. Tests marked known_blocked are quarantined with findings in docs/findings/out-of-scope-findings.jsonl.

Collection Integrity

PYTHONDONTWRITEBYTECODE=1 uv run pytest --collect-only must complete with zero errors. The test suite must be deterministic in clean clones. Stale pycache files, deleted conftest helpers, and orphan tests importing deleted modules are collection poison and must be removed.

Purge / Delete Policy

  • Tests for intentionally removed features must be deleted, not skipped or marked xfail
  • Each deletion must be documented in an audit note with the deleted module and replacement coverage
  • Stale stub/double files only referenced by deleted tests should be cleaned up
  • Test directory removal is only safe after verifying no non-failing sibling tests exist
