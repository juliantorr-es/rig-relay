# Frontend Rendering Safety Doctrine

## Status

**Draft.** Derived from Intake's security boundary policies and adapted for
Rig Relay's desktop cockpit frontend.

## Purpose

This doctrine defines the security rules the frontend must follow when
rendering backend-authored projections and user-provided content in the
desktop cockpit.

## Core Rules

### Rule 1: No raw session tokens in storage

Session tokens, API keys, and other authentication secrets must never be stored
in `localStorage`, `sessionStorage`, cookies, or IndexedDB within the frontend.
They exist only in the backend runtime and are passed to the frontend via
pywebview JS bridge or session-unique URLs.

### Rule 2: No raw prompts or model outputs in shared telemetry

The frontend may display raw prompts and model outputs in the chat view, but
must never pass them to any remote endpoint or log them to shared telemetry.
All telemetry events generated by the frontend are content-light (counts,
hashes, event names, statuses).

The canonical remote/shareable redaction helpers live in
`rig_relay.evidence.redaction`; frontend-adjacent bundle and audit code must
use that shared boundary rather than duplicating redaction rules locally.

### Rule 3: No plaintext sensitive data in long-term frontend storage

If the frontend caches backend data locally (e.g., IndexedDB for offline
support), sensitive fields (file contents, diffs, receipts) must be encrypted
before storage. Hashing is permitted only for lookup/deduplication of opaque
identifiers.

### Rule 4: No innerHTML for untrusted content

The frontend must use `textContent` (or equivalent safe DOM APIs) for any
content that originates from:
- Model outputs (prompt responses, generated code)
- User-provided text (chat input, task descriptions)
- File contents read by tools
- Shell command outputs (stdout/stderr)

`innerHTML` is permitted only for trusted, backend-authored HTML widgets where
the backend controls the entire HTML fragment and has sanitized it server-side.

**Exception:** Backend-authored widget HTML that has been sanitized by the
backend's projection builder may use `innerHTML` for structured widget layout.
The backend must not include untrusted content in these fragments.

### Rule 5: No eval or dynamic code execution

The frontend must never use:
- `eval()`
- `new Function()`
- `setTimeout(string)`
- `setInterval(string)`
- Dynamic `import()` with user-controlled paths
- Dynamic `<script>` element creation from untrusted strings

### Rule 6: No public/remote mutation authority

The frontend must not execute mutations (Git operations, file writes, shell
commands) directly. All mutations go through the backend:
1. Frontend emits an intent (via JS bridge or WebSocket)
2. Backend validates the intent (dirty guard, coordination leases, authorization)
3. Backend executes the mutation
4. Backend returns the result to the frontend

The frontend must not bypass this by falling back to alternative mutation
paths (e.g., direct `fetch` to a remote API, spawning a subprocess via
pywebview API).

### Rule 7: No cloud-side subprocess or Git commands

No backend running on a remote machine (telemetry store, cloud relay) may
execute subprocess commands or Git operations on behalf of the frontend.
These operations are local-only.

### Rule 8: Hash for lookup, encrypt for readable private data

| Data type | Storage approach |
|---|---|
| Opaque IDs (session_id, task_id, action_id) | Plaintext (non-sensitive) |
| Content for deduplication/lookup | SHA256 hash |
| Sensitive content (file contents, diffs, receipts) | Encryption (AES-GCM) |
| Secrets (API keys, tokens) | Never in frontend storage |

## Frontend Implementation Checklist

| Rule | Check | Status |
|---|---|---|
| Rule 1 | No `localStorage`/`sessionStorage` for tokens | ✅ |
| Rule 2 | Telemetry events are content-light | ✅ |
| Rule 3 | Cached sensitive data is encrypted | ⏳ Not yet caching |
| Rule 4 | `textContent` for untrusted input | ✅ |
| Rule 5 | No `eval` or dynamic code execution | ✅ |
| Rule 6 | All mutations go through backend intent API | ✅ |
| Rule 7 | No cloud-side subprocess/Git | ✅ (no cloud backend) |
| Rule 8 | Hash/encrypt pattern for storage | ⏳ Not yet caching |

## Test Requirements

- `tests/frontend/test_no_inner_html_for_untrusted_fields.mjs`: Verify that
  frontend components rendering system, model, or user-sourced text use
  `textContent` or equivalent, never `innerHTML`.
